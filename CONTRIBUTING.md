# Участие в разработке

Проект развивается с помощью ChatGPT. Изменения, подготовленные вручную или с помощью
ИИ, проходят одинаковую проверку: автор должен понимать код, описать поведение и
привести результаты тестирования. Вклад принимается под MIT-лицензией проекта.

## Изменения кода

1. Для ошибки приложите воспроизводимый сценарий и ожидаемый результат.
2. Сохраняйте изменения по одной теме; отдельно отмечайте несовместимые изменения API.
3. Версии зависимостей и внешних плагинов меняйте в `gradle/libs.versions.toml`.
4. Соблюдайте `.editorconfig` для Kotlin и `.clang-format` для C++.
5. Объясняйте в комментариях владение, ограничения ОС и порядок операций, а не очевидный синтаксис.

Не меняйте порядок блокировок, callback-фильтры или обработку отмены без проверки
соответствующих сценариев. При изменениях JNI обновляйте Kotlin, exports C++ и строковые
дескрипторы вместе. Числовые GATT handles нельзя заменять UUID-ключами.

## Проверки перед pull request

```powershell
.\gradlew.bat :gpt-ble-manager:allTests :gpt-ble-manager:assemble :sample-windows:classes
```

Native-тесты запускаются через CMake/CTest, как описано в
[README C++](gpt-ble-manager/src/windowsMain/cpp/README.md).
Для проверки метаданных публикации используйте `:gpt-ble-manager:publish` — по умолчанию
результат находится в `build/repository` и не отправляется во внешний сервис.

Укажите, какие платформы и устройства реально проверены. Host-тесты Android не заменяют
проверку Bluetooth stack на телефоне. Не отправляйте неизвестные команды записи в устройство;
используйте документированный протокол и явно согласованный сценарий.

Не включайте `local.properties`, ключи, сборочные каталоги, дампы с личными данными и
адреса собственных устройств в коммит. Уведомления о лицензиях поставляемых инструментов
и зависимостей сохраняйте при обновлениях.
